REPOSITORY INTERFACES FOR THE CLAY / STRING / HYDROPHONE INSTRUMENT
Inspected 24 October 2026. Read-only inspection of explicitly selected main branches; no repository edits, runs, or commits. Hashes below are Git blob hashes, not commit SHAs. The hardware application and adapters are proposed; the listed mathematical implementations already exist.

1. DynaComp should own the measured dynamical model.
Source: https://github.com/towre676-cloud/DynaComp/blob/main/README.md ; blob 7b0d4ace093669c8f48fb45f6d34cc701103199e.
Current source advertises exact linear/sparse output quotients, controlled-polynomial lifts, switched coefficient-family closure, finite/all-time residual bounds, and stability certificates. A linear reduction packet checks EA=GE, EB=H, DE=C; an approximate packet must include initial-state, transition, input, and (for a physical instrument) separately added model discrepancy budgets. The README documents infinite-source spectral tails, too. The physical adapter must first supply a defensible calibrated A,B,C or controlled polynomial model. Rationalizing fitted decimals makes a replayable nominal model, not an exact law of clay.
Proposed contract: fusion.model/1 with sample_period_s, state_names/units, input_names/units, A/B/C rational strings, calibration_run_ids, valid amplitude/frequency/moisture/temperature domain, initial/input boxes, omitted-mode and discrepancy bounds. Outputs: encoded target dynamics, independently replayable algebraic identities, output-error envelopes or explicit rejection. Compare to a directly fitted low-order SLS/envelope model and full numerical reference; include construction and acquisition costs. No guaranteed speedup follows from source benchmarks.

2. Singularity should choose finite experiments and expose blind directions.
Sources: https://github.com/towre676-cloud/singularity/blob/main/docs/specifications/OPERATORS-v1.md ; blob aa629227ad407bea67c18e03c80961948bb2daa4. https://github.com/towre676-cloud/singularity/blob/main/src/singularity/panels.py ; blob 974e542b5b8212da240080629df2b5a2e4641d39. https://github.com/towre676-cloud/singularity/blob/main/docs/chapters/15_operators_experiments.md ; blob 435396147f6d18b22731cad634d2dcca464c2567.
Already implemented: OperatorSystem, observable_closure, verify_certificate, quotient updates, cheapest distinguishing action word; reading_pool(costs,readings,labels); minimum_cost_panel; exhaustive/greedy comparators; box and Euclidean consistency decoders. Exact public scalars are int/Fraction; floats are rejected. Pool row e has one scalar reading prediction for each finite candidate c. Box-noise pair coverage needs |r_e(a)-r_e(b)|>2*epsilon_e. This is conditional on valid candidate predictions and noise bounds. General continuous material identification is not automatically covered.
Proposed contract: fusion.experiments/1 with finite specimen/history hypotheses, admissible drive words, sensor-feature labels and units, predictions, per-feature uncertainty, reset requirements and physical time/energy/wear costs. Adapter returns a certified separating panel, an ambiguity list, or no panel within the declared pool. Begin with a full simultaneous sensor set; only reduce after cross-batch confirmation. A microphone alone can miss string/tank ambiguity, and a hydrophone alone can miss clay state.
Measured-source caution: https://github.com/towre676-cloud/singularity/blob/main/applications/sensor_replay/README.md ; blob 9907aa7fe0797a7ede97286d915268b665087f9f. Previous audio reductions fail held-out preservation margins; MIMII nominal pair also fails protected-machine margin, noise/class selection can require all eight channels, exact selection need not beat pruned greedy. These findings argue for conservative sensing on the new object.

3. PerfectJet should check target recoverability and bounded choices, with its finite Observatory for protocol state.
Sources: https://github.com/towre676-cloud/PerfectJet/blob/main/src/perfectjet/workflow.py ; blob fe862b5f538ed49a610da96e72f428bf79e2ec93. https://github.com/towre676-cloud/PerfectJet/blob/main/src/perfectjet/observatory/__init__.py ; blob 0cf0d4bc128e61d95cb919b5f07cdac10bb66483. https://github.com/towre676-cloud/PerfectJet/blob/main/docs/MATH_LAB.md ; blob 6a6c92e4463b8b72bff26400568871d71bfdd84b.
Already implemented: decision_pipeline(spec) accepts observation H, observed y, target rows G, positive-cost candidate sensors, nonnegative integer resource costs/capacities and caller-supplied deterministic errors. It reports needs_measurement with a nullspace/repair, exact_tie, needs_tighter_bounds, or settled only if one lower bound exceeds every competing upper bound. Scope: <=14 items, <=12 latent coordinates, <=3 resources, <=12 repair sensors; exact nominal measurement centers must fit one latent state. It does not solve arbitrary inconsistent noisy-center feasibility or fit a nonlinear rheological model.
Observable dynamics exports: compile_system, behavioral_quotient, HistoryPopulation, adaptive_experiment, pair_experiment, compile_observable_closure, compile_series. Use this finite system for READY / conditioning / loading / settling / probe / read / invalid, retaining which historical state is the identification target. A reset can erase clay memory, so it must be an action in the model rather than presumed harmless.
Proposed contract: fusion.decision/1, one requested physical target and tolerance, nominal linear observation relation in the calibrated chart, unit-carrying error terms, candidate additions. For decisions such as choosing the next drive from a supplied menu, retain uncertain contenders. Never interpret arithmetic exactness as experimentally exact knowledge.

4. PerfectPower should allocate resources and enumerate admissible drive/program menus.
Sources: https://github.com/towre676-cloud/perfectpower/blob/main/python/perfectpower/planning.py ; blob d56de57854764e2d4e97fab161b39436366bbaed. https://github.com/towre676-cloud/perfectpower/blob/main/docs/COMPLETION_PLANNING_MONOGRAPH.md ; blob ab56bc15179052b09a7eb4043f9b6da80ff70cc8.
Existing CompletionPlanner(specification) supports kind allocation or words, exact counts, rank/select, completion counts, optima/all ties, compatibility machines and explicit work budgets. Allocation source requires 1..16 resources and 1..64 named variables with integer resource costs, bounded quantities and exact rational objective profits. The words language preserves chronology and uses positive action costs. WorkLimit does not mean empty population.
Proposed contract: fusion.program-menu/1, a finite catalog of drive pulses/tones, delays, clay placements or cartridge choices, defined amplitudes, measured cost weights, transition guards and budget. PP can rank/count admissible sequences; it does not synthesize arbitrary stable continuous control. A drive sequence is executable only after the hardware layer checks force, travel, string tension and clipping limits independently.
Branch caution: perfectpower default is still claude/laughing-lamport-qqzdo9, while the inspected sources are main. Consumers should pin an explicit source ref rather than silently reading the repository default.

5. nonlinearhamiltonian supplies a mathematical reference and exact algebra tests, not the lossy material law.
Sources: https://github.com/towre676-cloud/nonlinearhamiltonian/blob/main/research/hamiltonian/README.md ; blob 3569d4333d7f7995d6a7a12af7ad2f19af150b4f. https://github.com/towre676-cloud/nonlinearhamiltonian/blob/main/research/hamiltonian/partner_lab.py ; blob 41de0b66bca5b877cc5b4e40e991a131e5dfc7ec.
Existing partner_lab.py parses rational q,p polynomials and offers exact Poisson/Moyal bracket comparisons, homogeneous kernels, all-degree supported monomial classifications, core-demo, and flow examples. The main research scope explicitly excludes analytic operator domains and global physical flows. Dynamic-core invariance differs from one-step exactness. Current clay/string mechanics can use a classical conservative baseline H(q,p)=p^2/(2m)+kq^2/2+alpha*q^4/4 and its verified bracket identities; viscous/plastic internal variables, hydration drift and fluid radiation must be added explicitly. None of the cited algebraic identities proves quantum behavior or computational advantage of a clay object.
Proposed contract: fusion.symbolics/1, declared conservative Hamiltonian, candidate target observables, exact symbolic derivative identities and clear list of missing dissipative/memory forces. The symbolic tests can help catch a wrong sign or a hidden nonclosing observable. Do not force the physical device into an exotic polynomial family to match a theorem.

6. Shared acquisition and evidence record is the missing new implementation.
No reviewed source establishes a ready-made clay/hydrophone acquisition driver, physical calibration, synchronous audio/force/geometry capture, live controller or measurement certificate for this proposed object. Build these as a small independent adapter rather than claiming the repos are already wired together. Save fusion.run/1 JSON plus raw multichannel WAV/CSV, specimen ID and history, all calibration factors and units, sensor coordinates/orientations, sample clocks, drive command and measured drive, moisture/temperature/mass, clipping flags, missing samples, code source refs, model version and physical-domain validity. Derived features must retain raw-run IDs.
The whole evidence chain is acquisition -> calibration/feature extraction -> model/prediction bounds -> experiment menu -> bounded decision -> hardware command -> measured response -> independent replay. No mathematical optimizer should bypass the instrument's local actuator limits. Initial practical scientific claim: distinguish prepared material histories from repeatable physical responses across unseen cartridges/days, and compare prediction error/cost to simple rheological and signal-feature baselines. Reservoir computing, logic gates, music-controlled computing and controller speedups are later hypotheses requiring separate held-out demonstrations.

FINAL INTEGRATION AUDIT ADDENDUM
The ordered-word PerfectPower route has one exact integer cost budget 0..256, <=16 actions and action costs1..16. It is not a native simultaneous time/energy/wear budget solver. Additional limits need explicit guarded-state encoding; an upper-budget menu must aggregate exact budgets or validate padding. The inspected nonlinearhamiltonian parser is a single scalar canonical pair q,p: restrict this instrument adapter to one selected modal conservative reference. The final mechanical layout uses four leaves in two Y-separated pairs and still requires measuring parasitic bridge pitch.
